# Skillz

`skillz` turns one native plugin repository into installable Claude Code, Codex,
and OpenCode packages. It does not own a global skill directory, launch an LLM,
or install aliases on a developer machine.

The source harness remains canonical. Generated harnesses contain portable skills
and resources; target-specific runtime behavior must be implemented as an
explicit override rather than silently copied.

## Add support to a plugin

Run this in an existing plugin repository:

```bash
cargo run --manifest-path /path/to/skillz/Cargo.toml -- init \
  --source opencode \
  --skills-path dist/skills
```

`init` writes `skillz.yaml`, an `INSTALL.md`, and `.github/workflows/skillz.yml`.
The generated workflow validates every push to `main` and publishes the current
build to the repository's `skillz-build` branch after a successful push build.

## Build locally

```bash
cargo run -- build --config skillz.yaml --output .skillz/build
```

The output has the following layout:

```text
.skillz/build/
├── .claude-plugin/marketplace.json
├── .agents/plugins/marketplace.json
├── claude/
├── codex/
├── opencode/
└── skillz-report.json
```

Use the generated branch as a mutable tracking install and use release tags for
immutable installs. The report identifies when a target needs a runtime override.

## GitHub Action

The repository is a composite action. Consumers normally use the workflow
generated by `skillz init`:

```yaml
- uses: dylanOshima/skillz@v1
  with:
    mode: publish
```

`mode: build` only creates an output tree for a CI artifact. `mode: publish`
appends a generated commit to the configured distribution branch; it never edits
the canonical source branch.
